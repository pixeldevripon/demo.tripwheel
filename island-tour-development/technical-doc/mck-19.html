MCK-19

Where an activity hub lives in discovery

The Curaçao page already routes people to Klein Curaçao, twice: in the hero quick links and as the first tile under Explore by type. What it does not do is say what kind of thing it is, so a place is dressed as a category and given a tour count that sits next to the category counts. The nav dropdown, meanwhile, has no way in at all. Two small changes, no new page and no new section: give the place a label instead of a count, and give the dropdown a row.

1 · The Categories dropdown

This is the one surface with no route to a hub. The row goes above the categories rather than inside the list, because master 2.4 defines the list as drawn from the 19 global categories and because the sets overlap: the same boats sit in Klein Curaçao, in Day Trips and in Boat Tours at once. A rule and a pin carry the distinction; the row takes no count, for the reason under the drawing.

Why the row has no count, and why this is already live. Every category row counts tours in that category. A hub is not a slice of the catalogue, it is a place, and its number depends on what you count: the shared day trips, or those plus the private charters. On the Curaçao page today the place tile reads 10 tours two tiles away from Day Trips, 9 tours, and the hub’s own page shows nine day trips, so the same product has two numbers and neither is explained. Replacing the count with what kind of thing it is fixes the ambiguity and the arithmetic in one move.

What this is, and what it is not.
  • It is not a hub becoming a category. The category list still draws only from the 19 in 2.4, which keeps the slug registry’s separation of hub and category intact in the UI as well as in the URL space.
  • It is not a new section, a new tile or a reorder on the destination page. 5.2’s order is review-locked and stays as it is; one tile loses a number and gains a label.
  • The place tile carries no tour count, for the reason above, and its label says what kind of thing it is.
  • On mobile nothing changes: the dropdown keeps its rule and the destination row keeps its horizontal scroll, with the place tile already in first position so it is on screen without scrolling.
  • Both surfaces use the pin the tour card eyebrow already uses, so a place reads as a place everywhere on the platform.
  • No group headings in the dropdown, decided August 9. The trigger button already says Categories, and the hero quick links on the destination page already run a hub, a collection and a category together in one unlabelled row, so an unlabelled mixed list is the pattern this platform already has rather than a new one.
Three things to settle before this is built.
  • 2.4 needs one sentence either way. It currently says the curated discovery list draws from the 19 categories, full stop. If a hub gets a row above the rule, that sentence has to say so, or the next person to read 2.4 removes the row as a bug. Same edit, same day, as the 3.5 note that is already owed.
  • Which hubs qualify. Klein Curaçao is obvious. Willemstad is a hub too. A rule is cheaper than a judgement call per island: a hub appears here when it has its own page and a minimum number of bookable tours, the same shape of gate 2.4 already applies to categories below three published tours.
  • Autocomplete first. The search panel is the one surface already specced to offer hubs as their own entries, and it does not. Fixing that is smaller than either change here and it is already a finding, so it is worth doing in the same pass rather than after.
