MCK-16

Availability agenda, the Calendar section

The build has two dated surfaces that write the same departures. Tours › Schedule › Calendar got the August 7 rules: the close asks a reason, the day card names the consequence, the legend carries four states. Calendar in the sidebar did not, and that is the one an operator actually lives in, because it is the only place that shows every tour at once. This file applies the rules that already exist on the tour surface to the agenda. Same shell, same grid, same pill anatomy, same button style. No new design language, nothing invented.

Everything below is live. Switch the seat at the top right, click a departure, close it, undo it, add one, close a range. The three seats are the three the access matrix defines, and they change what you are allowed to do rather than only what you can see.

1 · The agenda, live

The build opens on Day. This opens on Week, because the decided agenda horizon is today plus six days and a week grid is that horizon in one screen. Day keeps its place as the mobile default and becomes the chronological list the July 29 review specified, instead of a one-day hour axis. Both controls already exist, so nothing is added to the shell.

Island Tours
Demo controls only, not part of the surface. The warning renders by itself when a tour runs out of open departures, which cannot happen inside one demo week, so there has to be a way to look at it.

3 · What does not change

So nothing gets rebuilt that is already right. The build got more of this surface right than the finding list suggests.

  • The shell: nav, header, date title, Today and the arrows, the mini month, the filter block, the Day, Week and Month switch. All kept.
  • The week grid itself: hour axis on the left, one column per day, today ringed, past days faded and read-only. Kept exactly.
  • The pill anatomy: tour name, then time and booked of capacity. That is the July 29 spec, and unit-priced tours correctly do not show a seat count.
  • The footer line "All times are local to each tour's island. Counts show Island Tours bookings only, closing never touches booked guests." That sentence does three jobs at once and it is already there.
  • Close or reopen a range. It is the blackout the dev spec asks for, it works, and it doubles as the weather-day action, so no separate Close today button is needed (founder, August 11 2026). The dev spec asks for one-tap Close today and Close tomorrow, written before this control existed; the range tool covers the capability and the shortcut is not worth a button that closes a day of revenue in one tap on a phone. Two changes only: open it on the day being viewed with All tours preselected, and ask the reason.
  • The overflow chip when a time band holds more departures than fit. Keep it, but it should open the day rather than only expand in place.
