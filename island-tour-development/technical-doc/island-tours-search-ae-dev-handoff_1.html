Note from Denley: why this change

What is wrong with the current search. It works functionally, but it costs us the hero. On mobile the white card is roughly 400px tall, the two fields have no borders so they read as loose grey text on white, and together the card and the button hide the destination photo, which is our emotional sell (tours picked by locals). The whole first viewport goes to one interaction.

What the new design is. One pill: both fields and a round orange search button in a single bar (the segmented-pill pattern travelers already know). On mobile that is one 56px row, so the photo owns the fold again. And mobile only: once the hero scrolls past, the pill docks below the nav, so search stays one tap away on a long page. Desktop does not dock, because the nav search is already the persistent entry there. Mobile placeholders shorten to What? and When? so nothing truncates; desktop keeps the full question; aria-labels stay full on both.

What does not change for you. Your DOM and ids exactly as they are (q, dateinput, datefield, datepop, dgrid), the single-month picker, the unified autocomplete (5.10) and the submit contract. This is a CSS-level change plus about 18 lines of JS; the deltas below are copy-paste ready.

One more spec catch while you are in this file: the live build shows 4 popular links under the hero; master 5.2 locks the top 3 from the curated discovery list. The demo below shows the exact three (with the live URLs).

JS addition (before </body>)

// dock (mobile only) + placeholder swap; ids q / dateinput / herosearch as-is
(function(){
  var hs=document.getElementById('herosearch');if(!hs)return;
  var hero=hs.closest('.hero')||hs.parentElement;
  var mq=matchMedia('(max-width:767px)');
  function ds(){
    if(!mq.matches){document.body.classList.remove('hsdock');return;}
    var b=hero.offsetTop+hero.offsetHeight-64;               // 64 = nav height
    document.body.classList.toggle('hsdock',window.scrollY>b);
  }
  function ph(){
    var qi=document.getElementById('q'),di=document.getElementById('dateinput');
    if(!qi||!di)return;
    if(mq.matches){qi.placeholder='What?';di.placeholder='When?';}
    else{qi.placeholder='What do you want to do?';di.placeholder='Select date';}
  }
  addEventListener('scroll',ds,{passive:true});
  addEventListener('resize',function(){ds();ph();});
  ds();ph();
})();
Accessibility and rules baked in: mobile touch targets 48px and up (circle 48, fields 56 row height); the icon-only search circle passes the WCAG non-text 3:1 rule (white on #E8611A computes 3.41); focus-within ring on the pill, focus-visible on controls; reduced motion collapses transitions and keeps scroll-behavior auto; the dock is a class toggle, no animation.
