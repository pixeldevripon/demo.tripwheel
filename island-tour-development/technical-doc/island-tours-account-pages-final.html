Dev notes (build reference, not part of the page)
Demo data
  • Mirrors the July 29 dev test set, now on real register tours (titles per the approved content packages), with these deliberate corrections: refs regenerated in the E.8 display_ref format (IT-2026-XXXXX, ambiguous characters excluded); the $181 booking's deposit set to a valid LD24 rate (20%, $36.20; the test set's $41.70 is 23%, no tier rate); the on_arrival slot is the east coast buggy tour and one past operator_full booking was added so all four payment models render; meeting points and operator names are demo values (LD10 sanctioned example names).
  • Weekday dates computed for 2026; deadlines are start minus cancellation_hours (48h demo default), rendered "{Day, DD Mon, HH:MM} (local time)" per 4.4.
  • Photos are real media-system frames (named sets of tours 01, 10, 13, 14, 17 and 25), downscaled to small inline previews for this demo; production loads placement sizes through the media pipeline. Operator phone numbers and email addresses in the support rows are demo values; the Miss Ann pair mirrors the confirmation-email wireframe.
State model on this surface
  • confirmed · completed (derived) · cancellation_requested · cancelled · operator_cancelled · forfeited (copy to be locked before render) · pending_payment never lists. One state per booking, chips per DIT-7 (white chip, ink label, hairline, state dot; payment chips green-tint or paper).
  • Cancel request: inline confirm strip with the 6.4 copy ("Cancel {tour}, {date}? Refund {amount}.", refund line only above zero); confirm submits the manual request, chip flips to Cancellation requested. Demo wired on the 14 Aug card.
Hard rules carried from the master
  • No Pay button anywhere in the account area: payment links exist only in the operator's balance email (6.7). operator_link balance lines never claim paid or unpaid (conflict log 84/85); "Paid so far" does not exist.
  • Cancelled bookings render the locked model-aware 6.4 refund copy; every refund also appears as a Payments entry with its own state.
  • Cross-booking view plus Payments sit behind the email-code step-up (login spec O2); 24h session, logout always visible, SSR never cached, noindex. No voucher downloads (LD4: reference plus ID is the check-in credential).
  • All strings via next-intl; "travelers" US spelling locked (4.3); reference placeholder never localized; no emoji, Lucide-family icons only (LD20); em-dash count in copy: zero.
In the build, not in this demo
  • Empty account, past-only, operator_cancelled, forfeited, and payments-empty states: copy in review section 5.9.
  • Nav and footer are static stand-ins for the shared components; "Open booking page" links to the per-booking (pair-credential) surface.
  • Receipts and invoices deliberately out of v1 until an invoice template is specced (review section 9).
  • v1.1 OTA-pass additions marked proposed in review section 10: Add to calendar (needs an .ics endpoint), Book this tour again on completed trips, Maps links resolving from the tour record's meeting-point geo, and the operator-first support row (5.9 order). Self-service date change stays V2 (review 10.4).
